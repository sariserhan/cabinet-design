# Job workflow: site to installation

Open **Designer → Job workflow · site to installation**. Enter the person recording the checks at the top.

1. **Site:** review each wall, room geometry, opening and recorded service point. Enter actual readings and notes, then choose **Checked and matches** or **Needs correction**. Attach up to eight captioned site photos. Existing room geometry is edited in the Room stage; the guided measurement wizard creates a new measured room. Changed dimensions invalidate the affected evidence.
2. **Options:** save the current design as Good, Better or Best, with explicit scope and exclusions. Make the changes for the next option and save it in another tier. Compare plans, finishes, item counts, changed fields and illustrative estimates. Export a printable HTML comparison. These estimates are not supplier quotations.
3. **Order:** review fillers, finished ends, accessories, exact appliances, supplier pricing/availability and each supply item's specification. Enter source references. Calculated geometry/installation warnings and unresolved site questions also block reviewed release; manual acknowledgments cannot clear them.
4. **Revisions:** save a named snapshot with its reason. Compare exact changed fields with the current design. Record customer sign-off only after receiving it outside the app; include the customer's name and evidence reference. This is an operator-entered record, not an authenticated electronic signature. Changes to room, items, finish, measurements, quote or site notes require sign-off for the new content before reviewed release.
5. **Handoff:** download a draft at any time after entering a preparer. Reviewed export requires all current checks and sign-off. Extract the ZIP and open `index.html`. It links numbered drawings and elevations, dimensions, CSV items, site photos/notes, review evidence and an installation checklist. Drawings remain coordination documents; reviewed status does not certify manufacturer compliance.
6. **Pilot:** record separate dealer and installer sessions. Keep rehearsals classified as rehearsals. A blocked attempt needs a documented fix before a passing retest. Results are tied to the tested design and evidence category, so old or synthetic results do not become current real-project passes.

## Pilot protocol

Use a representative project and retain the original measurements and supplier documents. Ask participants to work without coaching first; record assistance as a blocked attempt.

| Participant | Task | Evidence to record |
| --- | --- | --- |
| Dealer | Enter room, openings and services | Time, missing fields, incorrect dimensions, navigation problems |
| Dealer | Prepare three options and revise scope | Whether differences and pricing basis are understandable |
| Dealer | Review the order and record received approval | Missing products/accessories, unclear checks, evidence references |
| Installer | Locate every item from the handoff | Ambiguous marks, missing dimensions, mismatched item list |
| Installer | Check the site and service notes | Missing readings, photos or service positions |
| Installer | Report an issue and review the correction | Reproduction steps, fix, changed revision, independent retest |

Export the pilot report after each session. Fix reproducible product issues and repeat the affected task. A completed software rehearsal is not evidence that a dealer or installer has used the product successfully on a real job.

## Storage and recovery

Job records are scoped to the account and project in browser storage. Complete project backups include them. Cloud/shared-project records do not sync this new workflow yet. Importing records or restoring a backup preserves findings and photos, resets verification status, and removes recorded sign-offs so they must be reviewed again. Conflicting writes from another tab are rejected instead of overwriting newer records.
